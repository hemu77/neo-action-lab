# Norton Neo: action threat model

This model assesses the proposed architecture, not a deployed browser. The attacker controls page prose, labels, embedded frames, scripts, and timing, and may operate or compromise an allowed site. The attacker cannot change browser chrome, the local signing key, the deterministic Gate, or a reviewed adapter without a separate compromise. Protected assets include private user values, credentials, task scope, account state, and the user's attention.

The privileged decider is the deterministic Gate. The Planner is a compiler input, not a policy authority. Only the Reader sees arbitrary page text. A page-selected candidate may influence a permitted choice, but cannot add operations or authority. Taint follows derivation; sensitive destinations and values must originate in the Intent Contract. Scope is an exact HTTPS origin, with no automatic subdomain authorization.

**Verdicts:** Stopped means the specified attack path is denied under the stated instrumentation and adapter assumptions. Reduced means a control narrows exploitation while a remaining path exists. Accepted means a named residual risk is deliberately retained, subject to release-owner approval. These are design assessments, not measured attack-success results.

## Why the accepted risks remain

**T13 — choice quality.** A useful assistant needs to choose among available times, items, or search results. Prohibiting all page choices would remove that usefulness. Deterministic parsing establishes literal agreement with the contract when possible; it does not establish real-world quality. The release owner accepts bounded recommendation error while requiring confirmation for a differing nonsensitive option. A bad choice that also crosses scope, payment, or disclosure boundaries is denied, not accepted under this risk.

**T14 — destination trust.** An intended recipient must receive some data to complete a reservation. After that disclosure, the browser cannot control the merchant's server or prove that a promised table exists. The design limits the fields received, uses reputation as a warning signal, and attributes results to the site. Acceptance covers downstream misuse and dishonest outcomes, not open redirects that bypass origin checks. A new redirect destination requires separate user-authorized scope.

**T15 — human attention.** Consequential actions need meaningful user consent, but repeated prompts can erode it. The policy combines reasons for one exact action, displays its destination and disclosures, and avoids prompts for literal matched reversible choices. The product team measures confusion and abandonment alongside prompt frequency. Acceptance does not permit eliminating mandatory money, credential, or commitment prompts to improve conversion.

## Validation and ownership

The red-team lead owns fixtures and adversarial variations; the browser-security engineer owns mediation coverage; the Gate engineer owns precedence and replay tests. Every case is paired with a legitimate control task. At minimum, replay the architecture trace and test both plaintext and transformed egress, same-origin public sinks, fourth redirects, expired contracts, stale confirmations, hidden fields, unsupported roots, malformed Reader records, and page-induced structured errors.

The working prototype exercises deterministic fixture decisions. It does not provide evidence that real browser transports, Grok sessions, Safe Web integration, or chrome confirmation meet these assumptions. Reclassify Stopped entries if instrumentation or adapter coverage is missing. Report attempted attacks, observed unauthorized effects, and clean-task success separately; aggregate accuracy can hide a severe boundary failure.
